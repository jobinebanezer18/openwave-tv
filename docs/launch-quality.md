# Launch quality audit and release gates

Status: independent source audit of OpenWave TV v0.2.0, 12 October 2026. This is a release decision document, not evidence that a device or store review has passed. The current repository builds desktop executables for Windows, macOS, and Linux; there are no iOS or Android packages, mobile device tests, accessibility audit results, or stream rights records in this repository.

## Release judgment

**Do not label the current catalog and player production ready on iOS, Android, or desktop.** The desktop download is a useful public alpha. The most serious gap is the absence of a documented right to distribute or present each third-party stream and logo. A GitHub playlist or an HTTP 200 response is evidence of a URL, not a grant of rights. Apple explicitly lists third-party audio/video streams, sports, and trademarks among cases where App Review may ask for rights documentation: [Apple review documentation](https://developer.apple.com/help/app-review/before-submitting-for-review/complete-review). A store submission or broad promotional launch should use a curated, rights-reviewed catalog first. This is a release gate, not a claim that a specific existing stream is unlawful.

The second gap is that the quality promise is broader than the checks. `main.go` accepts an upstream “online” flag, then probes only when someone clicks a channel. The probe checks recent HLS bytes and rejects empty MPEG-TS null packets, which is an improvement, but it does not prove decodability, audio, sustained playback, regional reachability, or permission to carry the content. The radio directory is fetched straight from GitHub and audio is played directly from station URLs without a current health test. Failed radio stations remain visible.

The third gap is release infrastructure: current CI runs Go and two JavaScript unit tests, creates cross-compiled archives on Ubuntu, and publishes a tag. It does not install or launch those archives on their target operating systems. It does not run browser flows, accessibility checks, platform signing/notarization, or staged releases. A green build is not a production quality signal yet.

## Prioritized findings

| Priority | Finding and code evidence | Required close condition |
| --- | --- | --- |
| **P0** | **Catalog provenance and permission are unresolved.** `main.go:getCatalog` merges an indexed playlist plus Free-TV and World IPTV backup URLs. `src/main.js` renders upstream channel logos. README correctly attributes metadata, but attribution alone does not establish streaming or logo rights. | Publish a per-source rights register recording broadcaster, URL, logo rights, allowed territories, playback/redistribution terms, contact and last review. Default production catalog must be allowlisted; unreviewed sources remain opt-in for local developer builds only. Keep OTT providers as official links unless an authorized playback agreement exists. |
| **P0** | **Loopback API needs a hostile-page boundary.** `main.go` serves `POST /api/session` and media sessions on localhost without validating `Origin`, `Host`, or request `Content-Type`, and without request-rate or session limits. A hostile web page may be able to send blind cross-origin requests to a local server; CORS read restrictions do not alone prevent those requests. Session/probe maps can grow with requests. | Require local Host and same-origin Origin for mutating endpoints, reject cross-site simple requests, limit concurrent probes/sessions and cache size, set server timeouts and response body limits, and add negative tests from a separate origin. Re-review any proposed LAN binding separately. |
| **P0** | **No platform release evidence.** `.github/workflows/build.yml` cross-compiles on one Ubuntu runner; it neither executes the macOS/Windows binaries nor creates mobile packages. | Signed, platform-native install artifacts and physical-device smoke tests exist for every stated target. A release candidate is installed from its actual distribution path, launched, updated, and removed on each platform. |
| **P1** | **Availability is overstated by guide membership.** `main.go:probe` samples HLS manifests and 16 KiB of recent segments on selection. One global dead-channel flag suppresses a channel for 30 minutes even though failure can depend on country, network, codec, or source. The Go probe cache and catalog freshness are process-local. | Curated catalog has independent synthetic playback checks in every intended market and a clear state: playable here, restricted, unverified, or temporarily failed. Suppress a failed *source* for the relevant region before suppressing a whole channel. First-frame and sustained-play tests decide eligibility. |
| **P1** | **Radio is not measured as live or local FM.** `src/radio.js:load` accepts HTTPS MP3/AAC/OGG entries from a remote static JSON file; `playStation` sends the browser straight to the station endpoint. The FM toggle only filters metadata that happens to contain `fmMhz`; city data is station state/region text. | Verify a curated station set by successful audio playback in target regions, expose “FM frequency supplied by station metadata” rather than implying hardware FM tuning, and distinguish a city match from a guaranteed local broadcast. Add retry and replacement station handling. |
| **P1** | **Player recovery and UX lack end-to-end proof.** `src/main.js:playChannel` retries another HLS source only on fatal hls.js errors or native video `error`; a 15-second timer shows an error but does not advance to the next source. Manual retries can repeat a bad source. | Automated browser tests cover no frame, decode failure, temporary stall, autoplay block, source switch, back navigation, and channel click scrolling. A stalled feed advances once to the next eligible source and preserves a usable control path. |
| **P1** | **Accessibility of custom pickers and mobile targets is unproven.** TV and radio use `role="dialog"` with `role="listbox"` around `<button role="option">` elements, but their overlays do not trap focus or make the background inert. `src/style.css` uses several 35–43 px icon controls and 10–12 px text. Onboarding has a focus loop; TV and radio pickers do not. | Keyboard and screen-reader testing on all three platforms. Custom controls have valid name/role/state, logical focus restoration, no background focus while modal, visible focus, usable zoom, contrast, and touch targets. Fix actual failures before release. Target WCAG 2.2 AA; [W3C name/role/value](https://www.w3.org/WAI/WCAG21/Understanding/name-role-value), [focus visibility](https://www.w3.org/WAI/standards-guidelines/wcag/new-in-22/), [target size minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum). |
| **P1** | **Privacy claims need a complete data map.** `src/radio.js` keeps geolocation calculations local after user action, but direct radio playback exposes a listener's IP to each station. TV playback reaches stream hosts through the local proxy. The AI model downloads from Hugging Face on first use; channel logos and radio metadata also come from third parties. Local storage contains preferences and favorites. | Publish a concise in-app privacy notice listing exact network destinations and what each sees, plus a way to clear local data. Record actual requests on each platform and verify no coordinates or search text leave the device. Use foreground, user-initiated location only. [Geolocation requires permission](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation_API); localhost is treated as a secure context by browsers, but a packaged app needs its own permission review [MDN secure contexts](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Secure_Contexts). |
| **P2** | **Personalization persists per browser origin.** Preferences, favorites, recently viewed, and bad-feed flags live in `localStorage`; a desktop wrapper or mobile app with a different origin may appear to reset them. | Define versioned preference schema and migration/export path before moving the UI between localhost, app WebView, and native storage. Test fresh install, update, origin migration, corrupt state, and reset. |
| **P2** | **AI label and outcome need measured honesty.** `src/search.js:inferCategory` maps free text to one of 15 broad categories with a local MiniLM embedding and a fixed threshold; it cannot reliably find a specific show, program time, or mood beyond category inference. There are two search unit tests. | Keep the label and copy limited to what it does, test multilingual and ambiguous queries from launch locales, and provide an ordinary text-search fallback if model download or inference fails. Measure relevance before promoting it. |

## Minimum release test matrix

Run this against the **packaged candidate**, not just Vite on localhost. Keep reproducible test fixtures for media failures and a separate, consented set of live broadcasters for smoke tests. Public upstream streams are variable; they are not deterministic test fixtures.

| Area | Scenarios | Platforms | Pass gate |
| --- | --- | --- | --- |
| Install/update | Clean install, signed launch, permission prompts, update preserving settings, uninstall; reject tampered package | Windows 10/11; macOS current and previous major; Android supported OS floor; iOS supported OS floor | All supported device/OS combinations pass; no warning caused by missing signing/notarization where applicable. |
| First run | Country/language/interests, skip or guest path if product requires one, reopen, edit, no catalog, corrupt local storage, low bandwidth | Small phone (375 px), tablet, desktop; keyboard and touch | User can reach playable content in at most three deliberate steps after launch; no dead end if a selected country has no channels. |
| TV | Curated playable HLS with TS/fMP4, audio-only and video, captions/alternate audio where available, geo restriction, 404/403, empty segment, stall, autoplay rejection, switch while loading, fullscreen | Safari/WebKit on iOS/macOS; Chromium on Android/Windows; Firefox desktop | On the vetted sample under 20 Mbps/100 ms, ≥95% reach first frame in 20 s, p95 first frame ≤12 s, and ≥95% play continuously for 10 min. Every failure shows an actionable recovery within 20 s. Track region and codec separately. |
| Radio | AAC/MP3/OGG on supported decoders, station 404, wrong MIME, redirect, slow start, background/lock screen, headset/Bluetooth controls | Physical iPhone, Android phone, macOS and Windows | ≥95% of the vetted station sample play audio within 10 s in allowed regions; pause/stop works in every app lifecycle state; no silent playing after leaving radio. |
| Discovery | Search by channel, country, language, category, city; no-result recovery; favorite persistence; 30k-item catalog stress; offline guide | Same platform set; with/without model cache | Useful fallback before model loads; zero wrong-country top results for explicit location queries in test set; no main-thread freeze >200 ms on target devices. |
| Accessibility | Full keyboard flow, screen reader, 200%/400% zoom, large text, reduced motion, color contrast, focus in overlays, touch targets, live status messages | VoiceOver iOS/macOS, TalkBack Android, NVDA Windows, keyboard-only desktop | Zero critical WCAG 2.2 AA failures in core watch/radio/onboarding flows; all overlays return focus correctly; no content clipped at 200% zoom. |
| Network/privacy | Capture outbound traffic at install, first run, normal search, AI search, geolocation grant/deny, playback; test hostile-origin requests against local backend | Every package and browser engine | Exact destinations match privacy notice; no coordinate/search leak; disallowed Origins/Hosts rejected; app remains usable after permission denial and network recovery. |
| Performance/soak | Cold/warm start, 2-hour TV playback, 2-hour radio playback, repeated 100 channel switches, memory and battery sample | Low-end supported Android and older supported iPhone plus desktop | No crash, runaway memory, stuck audio, or unreleased sessions; budgets measured and documented before final thresholds are frozen. |

The first numeric stream gates are launch targets, not current results. Use at least 30 independently rights-reviewed streams and 30 stations per launch region, checked on three different days and two networks; report numerator, denominator, and country for every claim. A region that misses the gate should ship with a smaller curated guide or remain unavailable in that region.

## Observability and rollout

1. Keep user analytics off by default. Synthetic probes and voluntary diagnostics can measure `catalog_loaded`, `session_started`, `first_frame`, `stall`, `source_switched`, and `ended` without a user account or precise location. Redact full stream URLs and IP addresses from public logs.
2. Dashboard by platform, app version, country/region, and source: eligible channel count, first-frame success, p50/p95 first-frame time, 10-minute uninterrupted playback, fallback success, radio start success, crash-free sessions, install/update failure, and accessibility bug count. Avoid a single global “working channels” number.
3. Roll out in layers: maintainers on signed packages → closed testers in one rights-cleared launch market → 5% public release → 25% → full release. Hold each stage at least 48 hours and include a weekend before a broad launch. Freeze catalog changes during a candidate build except urgent takedowns.
4. **Stop/rollback rules:** any confirmed rights or privacy incident; app crash or launch failure >0.5% of candidate sessions; first-frame success <95% on the curated sample for two consecutive checks; a material regression in assistive-tech flow; failure to update/rollback cleanly. Remove a bad source remotely via the curated manifest, or pull the package if the app itself is at fault.
5. Make issue intake actionable: app version, OS/browser, channel/station ID, country at country-level only, timestamp, observed message, opt-in diagnostic bundle. Never ask users to post sensitive coordinates or copyrighted video clips.

## First implementation slice

Implement a **curated catalog and playback contract** before building four native shells:

1. Add a versioned catalog manifest with explicit rights status, territory, content type, logo grant, alternate feeds, and last review. Ship only allowlisted rows in production mode; keep imported community playlists in an explicitly experimental local mode.
2. Add deterministic HLS fixtures for healthy stream, empty segment, stale manifest, decode failure, blocked autoplay, and region denial. Change the player timeout to advance to another eligible source once, then show a precise recovery action.
3. Harden the loopback backend: validate Host/Origin and JSON content type, rate-limit probes and sessions, cap maps and response sizes, and add cross-origin rejection tests.
4. Run one packaged desktop smoke test and one physical iPhone/Android playback spike using the **same curated stream**, recording first-frame time and codec support. Do not select a wrapper architecture from a visual demo alone.

After that slice, revisit the quality gates with measured data. A beautiful shell around unreliable or unlicensed feeds would multiply the launch risk rather than improve the viewer experience.
