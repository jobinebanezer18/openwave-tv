# Privacy and network activity

Last reviewed: 12 October 2026. This describes the current OpenWave desktop/browser build in this repository. A future hosted or mobile edition needs its own review before release.

OpenWave has no account, cloud sync, or app-operated analytics in this build. Its Go process serves the interface on your computer's loopback address. Watching TV and radio still uses the internet: catalog providers, image hosts, model-download hosts, and the stations you choose receive ordinary network requests and can see your public IP address. Their logging and retention policies are outside OpenWave's control.

## What stays in the browser or local process

Country, language, interests, TV and radio favorites, the 12 most recent TV channels, and playback-failure timestamps are stored under the browser origin in `localStorage`. They are not automatically uploaded to an OpenWave account. The app sends a selected TV channel ID, requested language, and source attempt to its local Go process when you play a channel. That process keeps the catalog, health results, and temporary playback session URLs in memory; it does not create a viewing-history file. TV sessions become unusable after four hours and are removed on a later session creation or process exit. Failed-channel suppression lasts 30 minutes; the catalog is refreshed on a later request after 12 hours; probe results are reused for up to 10 minutes. Closing the process clears its memory.

If you import a personal M3U file, its channel names and URLs stay in the current browser tab and are not added to the public guide, favorites, or recents. Playing one sends its URL to the local Go process, which probes the stream and holds a temporary playback session in memory for up to four hours. Removing the file stops playback and clears the tab's imported list; the already-created Go session remains until it expires or the process closes. Neither the file nor its URLs are automatically written to browser storage.

Typing into channel or radio search filters locally. Pressing **Smart** can download MiniLM model files, then runs the search inference in your browser; the app's own requests do not include your search phrase. Model-file hosts still receive download requests. The model library may retain downloaded files in the browser's Cache Storage. The app does not currently offer a clear-data button.

**Use my location** asks the browser for location permission only when pressed. OpenWave code compares the returned coordinates with a city list loaded from the local app and uses the nearest city to filter radio stations. It does not put the coordinates in an OpenWave API request or send them to a geocoding endpoint. The browser or operating system may use its own location service to determine the position; its behavior is governed by your device and browser settings. Declining permission leaves manual country/city selection available.

## Network and data map

| Trigger | Destination and data sent | Where data is kept |
| --- | --- | --- |
| Opening TV guide | Browser requests `/api/channels` from the local Go process. Go retrieves channel metadata from IPTV Nexus and backup playlists from Free-TV on GitHub and World IPTV on GitHub Pages. Those hosts see the computer's public IP and a request user agent; the app does not attach your search text or saved preferences. | Catalog held in Go memory; no application disk cache. |
| Displaying channel cards | Browser may fetch channel logos from URLs supplied in the catalog. Image hosts see the public IP and browser request metadata. Logo images use `referrerpolicy="no-referrer"`. | Normal browser image cache, if enabled. |
| Playing TV | Browser sends channel ID, language, and retry number to `/api/session` on loopback. Go probes and fetches HLS manifests/segments from the selected broadcaster or stream host, then relays media locally to the browser. The stream host sees the computer's public IP, requested media URL, and a configured or fallback user agent and, where supplied by the catalog, a referrer header. | Four-hour playback session and short-lived probe/failure state in Go memory; browser stores the selected channel in recent history. No video recording in app code. |
| Importing and playing a personal playlist | The file is read in the browser tab. Only when you play an imported channel does the browser send that HLS URL to `/api/private-session` on local loopback; Go fetches its manifests and segments from the stream host. That host sees the computer's public IP and requested URL. | Imported list in page memory until removal/reload; playback URL in Go session memory up to four hours or process exit. No OpenWave cloud upload. |
| Opening radio | Browser loads the bundled station guide from the local app. With browser storage available, it checks the Verified Radio Streams JSON on `raw.githubusercontent.com` in the background at most once per day after a successful check, or after a six-hour failure delay. If storage is blocked or cleared, it may check again on the next visit. GitHub sees the public IP and browser request metadata. | Bundled guide in app files, latest valid remote guide in browser Cache Storage (`openwave-radio-v1`), next-check time in `localStorage`. Invalid or older remote data is discarded. |
| Playing radio | Browser connects directly to the chosen station's HTTPS audio URL. That host sees the public IP, station URL, browser request metadata, and possibly a referrer according to browser policy. | Radio favorite IDs in `localStorage`; no audio recording in app code. |
| Pressing Smart search for the first time | Browser downloads model files for `Xenova/all-MiniLM-L6-v2` from Hugging Face and any redirect/CDN hosts used by that library. Those hosts see the public IP and ordinary request metadata; the app passes the typed phrase to local inference, not to an app API. | Model and runtime files may remain in browser caches (`transformers-cache` where supported). |
| Pressing Use my location | Browser/OS obtains coordinates, and browser fetches `/geo/cities.json` from the local app. OpenWave code makes no network request containing coordinates. The browser/OS location provider may use network services. | Coordinates held in page memory for the matching operation; chosen country/city remain in page state, not saved by this feature. |
| Following GitHub or GeoNames links | Your browser opens that external site. | Subject to that site's own policy. |

## Retention and clearing data

OpenWave has no automatic expiry for preferences, favorites, recents, or the locally stored failure timestamps. Browser caches may persist until you or the browser remove them. Clear **site data and cached files** for the exact OpenWave origin in your browser settings to remove these values and downloaded radio/model data. The default desktop launcher uses `127.0.0.1:8765` so saved preferences survive normal restarts; a custom port creates separate browser storage. If you previously used older preview versions with random ports, their site data may remain under those prior origins until cleared. Closing OpenWave clears the Go process's in-memory catalog and playback sessions. This app cannot delete logs kept by broadcasters or other external hosts; consult their policies for those records.

Questions or data concerns can be raised in the [OpenWave GitHub repository](https://github.com/jobinebanezer18/openwave-tv/issues). This document will need revision if cloud sync, telemetry, hosted playback, or native apps are added.
